## Build

Generated with a small Python script that also validates the plan before writing any file. Checks that passed:

- every task outside Phase 2 starts and ends on a Sun–Thu working day; every Phase 2 task sits on Fri 18 / Sat 19 Dec;
- every finish-to-start predecessor finishes before its successor starts (milestones may share their predecessor's finish date);
- the three phases are contiguous and do not overlap; phase dates equal the span of their children;
- the `.gantt` file parses as valid JSON.

Files written to the outputs directory:

| File | What it is |
|---|---|
| `office-relocation-riyadh.gantt` | The onlinegantt project file: JSON in the Syncfusion Gantt task shape the site is built on — 3 phase rows with nested `subtasks`, `TaskID / TaskName / StartDate / EndDate / Duration / Progress / Predecessor / Milestone / Notes / resources`, a `resources` list (Anas, Sara, Khalid, Moving Company) and project settings. Opens via **Open** on onlinegantt.com. |
| `office-relocation-riyadh.csv` | Flat fallback with the same 35 rows (ID, phase, task, type, owner, start, end, working days, calendar days, predecessors, notes) — use it to re-key or import into any other tool if the `.gantt` file is rejected. |
| `office-relocation-riyadh-preview.png` | Rendered Gantt chart of the plan (owner-coloured bars, Fri/Sat shaded, move weekend in amber, milestones as diamonds). |
| `office-relocation-riyadh-preview.html` | The same chart as a self-contained SVG page. |

Two things worth knowing about the file:

- **Calendar.** onlinegantt's built-in weekend handling assumes Saturday–Sunday, which would shift a Sunday kick-off and Sunday-start tasks. The file therefore sets `includeWeekend: true` and carries explicit start/end dates, so the Sun–Thu working week and the Fri–Sat move days are kept exactly as planned. `Duration` values in the file are calendar days; the CSV shows both working and calendar days.
- **Format caveat.** onlinegantt.com only publishes that it saves a `.gantt` file; I could not fetch its application bundle to confirm the exact key names it writes (the site serves nothing to non-browser clients). The file follows the Syncfusion Gantt data model the app is built on, which is the most likely match. If **Open** refuses it, the CSV has everything needed to enter the 26 tasks and 6 milestones in about ten minutes.
